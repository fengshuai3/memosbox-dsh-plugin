# 0.2 开发与发布门槛

Mirobody 是必须交付的模块，不再延期为独立可选插件。`0.2.0-beta.1` 是开发版本，不代表上线验收完成。

## 已进入实现

- A/B：Wiki 安全文件入口、导航/路径、取消/恢复、版本与来源渲染；真实依赖链回归；MemOS 独立 scope、日志策略和显式幂等写入。
- C：锁定 Mirobody wheel/词库、Python 环境、DSH 受管执行、离线指标/单位/元数据和 macOS 隔离探针。
- D：文档来源定位、模型证据校验、不可变候选、分目的地批准、Wiki/MemOS 提交与恢复。
- E：精确 tarball 消费实例、实际依赖与核心完整性、CI 和公开文档。

以上为实现范围，不表示各阶段全部退出。每次候选版本仍需完整验证。

## 正式发布阻断项

1. DSH 视觉模型/OCR 真实往返、扫描/混合页恢复和失败页追踪。现在只报告 needs_ocr，不能声称扫描件已支持。
2. 真实健康内容的宿主历史/日志/通用工具隔离、受保护审阅、保留期限/导出/删除/备份专项验收。当前只允许合成数据，敏感模式拒绝。
3. 明确公开 OS/CPU 矩阵、CPython 正式再分发来源与许可、平台 wheel 闭包和资源限额证据。当前只有 macOS arm64 3.12 开发锁。
4. 补齐 DSH 升级/HMR 活跃任务、完整 agent loop、交互审批界面和远程模型回合矩阵。隔离 profile 已实测 CLI 安装/卸载、真实 Loader 禁用/启用、宿主审批、合成模型路由文档入库及新进程读回；这些不代替全部产品验收。
5. 语义记忆、后台总结/演化和旧库迁移尚未验收，不能静默恢复未审网络链。
6. 每个最终消费者制品重新审计；当前精选核心生产依赖审计未检出公告，来源/hash 已记录。构建依赖中的 adm-zip 中危尚在，安装脚本禁用且不进入消费者闭包。上游 npm MIT 与仓库 Apache-2.0 的许可差异需正式澄清，不能杜撰模块 LICENSE。
7. Git 仓库、维护者、安全联系入口、npm 发布身份、CI 跨平台实际结果，以及 CPython/嵌入原生库审计。Node SBOM、Python wheel 清单已提供，但清单不等于再分发许可或完整二进制审计。发布必须构建一次、测试同一制品、发布该文件。

## 基础检查

```sh
corepack pnpm run verify
corepack pnpm run verify:consumer
corepack pnpm run audit:release
```

Python 契约与真实进程测试必须使用明确准备的环境和合成 fixture。缺环境、缺模型、权限拒绝和 hash 错误要可见，不得标为成功。初始资源限额不是医学准确率、性能 SLA 或临床安全承诺。

旧目录、Docker 和密钥不自动迁入。可以继续用合成数据开发；真实数据、平台范围及社区发布需要维护者明确选择。
