# 正式升级与回退门槛

0.1.x 的共享 MemOS/Wiki 布局与 0.2.x 的 profile＋工作目录隔离布局不同。不能把改包版本、创建空数据库或将旧库复制到每个工作区当作迁移完成。

## 升级前必须确认

1. 由使用者明确每份旧 MemOS/Wiki 数据归属哪个 profile 和工作目录；不根据当前 shell 目录猜测全部历史数据归属。
2. 检查活动 DSH 进程与后台写入，安排停写窗口；正常停止服务，不对用户运行中的实例直接 kill。
3. 在插件根内创建唯一、私有的备份目录，保留原 profile 的 package.json、lock、Cordis patch、原安装包及停写后的完整数据库/Wiki。记录校验和。凭据单独保留原位，不复制进源码、报告或发布包。
4. 使用相同候选在独立 profile 完成真实对话与人工 Web 审批。候选的固定 Python 路径、锁摘要和包 SHA-256 应与测试证据一致。

## 迁移与切换

- 原 patch 可能包含 DSH 的 `!!js` 表达式。不要使用普通 YAML parse/stringify 把它们改成普通字符串；使用 DSH 支持的配置解析/序列化接口或局部保留标签的编辑。
- 旧 viewer/host LLM 配置在新版不是同等实现；明确新版本默认关闭 capture、显式写入、文档处理与模型外发，不能静默沿用旧版 true 值。
- 对旧数据先做只读清点及 dry-run，保存源记录到目标 scope 的映射；Wiki 保留来源/版本/回执，MemOS 使用已审查的导入路径。无明确归属的数据保留原样、不分发给其他工作区。
- 人工核对记录数量、抽样原文、查询结果及跨工作区负例后，才用 DSH 原生 `plugin add -w` 更新正式 profile，并保留完整配置。
- 重启后在正式选定工作目录做健康检查与合成 canary，核对包版本、runtime、读回和拒绝写入行为；测试通过前不要处理真实健康资料。

## 回退

- 停止新版本写入，另存故障现场和新产生数据，不覆盖旧备份。
- 恢复准确旧安装包、旧 profile 配置/lock 及停写备份；不要用旧代码直接打开已由新版本修改的数据库。
- 新版 venv、候选、备份保留原固定路径，不随意移动或删除。验证旧版合成查询与原数据读回后再恢复使用。

2026-09-15 已完成一条明确归属合成 trace 和一个 Wiki 页面的隔离演练，见 `release/evidence/migration-rollback-2026-09-15.json`：原生 CLI 升级、独立新库导入、新进程原生工具读回、跨工作区负例、保留新版新增数据，以及旧安装快照/旧数据离线恢复均通过。旧依赖重新解析遇到网络失败，因此回退必须保留完整已安装依赖快照，不能只保存旧 tgz 后寄希望于未来还能解析安装。

该限定演练不等于正式用户数据已迁移，不覆盖旧策略、技能、世界模型和旧版完整 embedding 启动路径。未拿到旧数据归属、维护窗口与人工验收结果时，正式 profile 保持原样并明确提示仍在运行旧代码。
